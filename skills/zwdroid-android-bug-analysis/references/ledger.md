# ledger.md — 台账规格与轮次协议

ledger.md 是**唯一真相源**:事实/假设/待验证/已排除/轮次日志全在这里。
**仅主 agent 可写(R4)**;subagent 只写自己的 findings。context 压缩或换新会话后,
**读 ledger.md 即可恢复续跑**——所以每一步都必须落盘,不能只留在 context 里。

## Schema
见工作区模板 `${CLAUDE_SKILL_DIR}/workspace-template/ledger.md`(复制即用)。要点:
- **状态行**:`状态 · 当前轮次 · 策略切换次数 · 源码开关`。
- **元信息**:用户输入原文,一律标注为假设(R8)。
- **已知事实**表:每条带 `证据 [原始文件:行号]` 与 confidence 与入账轮次(R1/R11)。
- **当前假设**表:2-3 条(R:S4),每条 支持/反对证据、概率、验证成本、状态(待验证/验证中/无法判定-冻结)。
- **已排除**表:陈述 + 排除理由 + 证据。被排除项**不再参与后续推理**。
- **缺口与待办**:需补抓 / 需问用户 / next_action。
- **轮次日志**:每轮一节。

## 轮次协议(R9)——每次状态转移后主 agent 必做
1. **新证据入账**:带指针 `[原始文件:行号]` 与 confidence 写入"已知事实"。
2. **显式声明丢弃**:本轮排除的候选移入"已排除"、无关切片标注废弃;**已排除项不得再参与推理**
   (这是对抗 context 腐烂的关键——不显式丢弃,旧假设会在后续轮次幽灵复活)。
3. **更新 next_action**。
4. 若发生策略切换/跨 session/锚点校正,在轮次日志显式记一笔(含原因与指针)。

## 新会话冷启动恢复流程
1. 读 `ledger.md`:拿到 状态、当前轮次、源码开关、已知事实、当前假设、next_action。
2. 读 `manifest/`(若已存在)——不重跑 ingest(幂等,但费时)。
3. 从 next_action 指示的状态继续;**不重做已入账的事实,不复活已排除的候选**。
4. 需要原文时按指针 `原始文件:行号` 回查,不依赖上一会话的 context 记忆。

## 写作纪律
- 证据一律回指**原始** `文件:行号`(R11),即使你读的是切片(切片行自带 `原始文件:原始行号|` 前缀,取前缀里的坐标)。
- 事实与假设**分区严格**:没有 grep/日志实证的推断只能进"当前假设",不能进"已知事实"。
- confidence 三档 high/med/low;凡 med/low 必在结论的"不确定性标注"里显式体现。
